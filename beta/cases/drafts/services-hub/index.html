Inside the work

One service area. Different jobs, clear next steps.

From the hub, people can manage a booking, build a grocery basket and choose how it arrives. Each screen makes the next useful action visible.

iFoodPartner commerce · Brazil · In build

Move from a useful list to a delivery choice.

An authorised iFood connection can reuse an existing customer relationship, avoiding repeated setup. The conversation builds the basket; product quantities and delivery choices become structured review steps. I contributed to this shared partner work, which remains in development.

The challenge

Useful capabilities were scattered across the assistant.

Booking an appointment, watching a price and building a grocery basket each need a place to start and a place to return. The hub brings those capabilities together, with pending work visible and distinct actions for requests that need a response and routines that continue in the background.

My approach

Three service patterns. One partner foundation.

I led the information architecture, screen design and clickable prototype around bookings, commerce and routines. Each has its own interaction pattern within a reusable service foundation. Intent-led entry points keep the task recognisable, while partner-specific configuration supports different providers. Engineering built the production implementation.

Generative UI

Design a vocabulary the assistant can compose.

I defined reusable, schema-backed result blocks for prices, flight options, receipts and briefings. The model can assemble an appropriate result from known parts; the interface gives each part a clear hierarchy and action. This provides a consistent design foundation for capabilities that would otherwise need separate bespoke screens.

Design decision

Use conversation to build. Structure to commit.

Natural language is useful for describing a basket. Reviewing products, quantities, delivery and payment needs explicit choices. I kept those steps structured so a misunderstood request can be corrected before commitment. Within the hub, a category with one task opens directly; a browsing level appears only when there are several choices.
