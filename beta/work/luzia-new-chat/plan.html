Make the first chat feel effortless.

A product definition for stripping the experience back to a live conversation, then adding complexity only when the data says the simpler foundation is working.

01 / The opportunity

From a product directory to a conversation.

The existing home asked people to choose from characters, tools and destinations before they had started. The experiment opens directly into chat: fewer decisions up front, a clearer first action, and a measured route back to the features people rely on.

02 / Release logic

Prove the base. Then build on it.

Each release has a gate, so feature restoration and wider rollout follow evidence rather than a calendar guess.

v0Shipped · 11 Sep

Strip it to chat.

New users only. Begin with the conversation, a compact composer, a smaller set of entry points and a reduced character choice.

Readout
D1 and D7 retention, activation, load latency; verify the Android routing issue is clear.
v1After the readout

Make the base case right.

Resolve issues revealed by real devices: composer height, character naming and selection, small-screen behaviour, thread access and navigation details.

Gate
v0 retention and activation read out cleanly; routing data is trustworthy.
v2Once v1 holds

Layer useful features back.

Revisit chat search, reminders, favourites and character discovery. Fix known usability gaps as part of the restoration, not as follow-up debt.

Gate
v1 retention does not regress; churn mitigation is written before existing users are affected.
v3When the base is safe

Widen rollout and identity.

Expand to existing users only after the restored experience holds. Bring back tools selectively and complete the identity work with brand approval.

Gate
v2 holds on the existing base; brand signs off the palette.
03 / v0 definition

A deliberate reset.

The first release creates a clean baseline. Scope is explicit so teams can separate the treatment from features removed in both arms.

01

Open directly into a new chat.

Login leads to chat. The welcome is short, icebreakers live near the composer and disappear when the keyboard is up or the composer has text. The New chat action moves to the FAB.

02

Keep a focused set of tools.

Keep visual tools, thread search, response settings and Plus in settings. The composer keeps Plus and the microphone; tool chips leave the composer.

03

Reduce the number of competing destinations.

Routines, services, widgets, standalone icebreakers, custom personalities, Plus promotion and search inside a chat leave v0. The character picker presents four named choices.

04

Make the cohort and rollout measurable.

Target new users through first_version ≥ brutal_simplification_version. The initial proposal was 10–20%; the final decision recorded on 11 September was a 50/50 split.

04 / Decision ownership

Keep design, product and engineering clear.

Every open item has an owner type. This keeps a visual decision from standing in for a product call, and an engineering constraint from being solved with another screen.

DES · Design

Interface and behaviour

Layout, copy, states, motion, responsive rules and front-end details. Design owns execution once scope is decided.

Examples: composer states, drawer behaviour, character names and small-screen icebreakers.

STR · Product / strategy

Scope and measurement

Audience, what is measured, which features return and the conditions for rollout. These decisions need product and leadership agreement.

Examples: rollout size, custom besties, routines and onboarding requirements.

ENG · Engineering

Platform and data integrity

Backend fields, native behaviour, analytics plumbing and defects. Resolve technical constraints with the responsible engineering owner.

Examples: deep links, thread routing and event targeting.

Risk to resolve before broad rollout: name and date-of-birth onboarding, including age verification, were removed from both arms. The roadmap source records no legal sign-off in the decision thread.

05 / Readout guardrails

Compare what actually changed.

The control is design intent from the shipped Chats Figma; confirm it against the build for the analysis window. The v0 source-of-truth page is current.

A

Do not treat shared changes as experiment lift.

Gamification entry points were removed from control and treatment, and icebreakers moved to the bottom in both. These are not treatment deltas.

B

Expect funnels to change shape.

The bottom bar disappears, the thread list moves into a drawer and the character catalogue shrinks to four. Events tied to the old surfaces may stop firing entirely, not simply decline.

C

Confirm the control build.

Control frames are 375 × 812 and treatment frames are 393 × 852. Read the comparison structurally; confirm chip state, tab labels and implementation before comparing pixels or events.
